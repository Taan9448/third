# 픽셀 애니메이션 에셋 배치

모든 시트는 게임 전용으로 생성한 RGBA WebP이며 원본 도트 그림의 프레임을 Canvas에서 잘라 재생한다. 이미지 보간은 끈다. 위치 이동만으로 공격을 대체하지 않는다.

| 시트 | 열×행 | 행 순서 | 프레임 |
| --- | --- | --- | --- |
| `assets/hero-attacks.webp` | 6×3 | 설아, 리라, 아리아 | 각 6: 준비 / 힘 모으기 / 발동 준비 / 공격 / 후속 동작 / 복귀 |
| `assets/enemy-attacks.webp` | 6×6 | 늑대, 정령, 갑옷 기사, 가시 여왕, 장문, 날개 마왕 | 각 6: 준비 / 예비 동작 / 발동 / 타격 / 후속 동작 / 복귀 |
| `assets/skill-frames-a.webp` | 4×8 | slash, guard, spark, ward, bash, protect, bond, moon | 각 4: 생성 / 성장 / 정점 / 소멸 |
| `assets/impacts.webp` | 4×4 | 검격, 마법, 화염, 빙결 | 각 4: 접촉 / 확산 / 폭발 / 잔해 |
| `assets/skill-frames-b.webp` | 4×8 | storm, lotus, heal, focus, nova, fortress, flash, frost | 각 4: 생성 / 성장 / 정점 / 소멸 |

갑옷 기사 시트는 암살자·마교주, 마왕 시트는 지옥왕에도 연결된다. 기존 몬스터 디자인과 비율을 유지하되 포즈를 추가했다. 여성 파티는 SD 비율이다. 대기에는 첫 프레임을, 공격에는 0–5 프레임을 사용한다. 아직 별도의 6프레임 대기/피격 시트가 있는 것은 아니다.

`src/animation.js`에서 프레임 수·인덱스·기술 행을 정의한다. `src/visuals.js`는 캐릭터 공격 1020ms, 몬스터 공격 900ms에 시트를 재생한다. `src/effects.js`는 4프레임 기술 그림과 기술별 경로·검흔·파편을 함께 그린다. `src/cast.js`는 파쇄 이후 540ms 동안 기술의 네 프레임을 재생하고, 도착 후 600ms 동안 독립된 타격 네 프레임을 재생하며 적중은 1060ms 시점에 한 번 발생한다. 합격절기는 전체 시간을 1.4배로 늘리고 월영천광/moon, 천체연쇄/nova, 서광성역/fortress 시트를 사용한다.

프레임 시트를 수정할 때 열·행 개수, 기준 바닥, 여백과 투명 배경을 유지한다. 생성 시트의 정렬·실루엣을 수작업으로 다듬는 작업은 이후 품질 보강 대상이다. `tests/browser_check.py`는 실제 브라우저 재생 중 캐릭터·몬스터 6개 인덱스와 기술 4개 인덱스를 수집해 확인한다.

## v5 프레임 경계와 발 위치

시트의 실제 인물 간 간격이 등간격이 아니므로 캐릭터·몬스터를 단순한 동일 격자로 잘라서는 안 된다. `src/sprites.js`는 로드 시 알파의 연결된 큰 그림을 분리해 런타임 텍스처로 캐시한다. 포즈마다 전체 실제 범위와 바닥 중심을 구하고 중립 자세 기준의 하나의 배율로 그린다. 가시 여왕의 두 포즈를 연결한 덩굴 구간은 해당 시트의 정규화 좌표에서 경계를 분리한다. 원본 에셋은 유지한다.

발 기준점은 모든 포즈에서 같은 전장 지면에 놓인다. 모든 프레임의 폭·높이를 함께 확인해 캔버스 밖으로 나가지 않도록 배율을 제한한다. 생성 시트를 교체할 때는 캐릭터가 배경과 분리된 투명 그림인지 확인하고 경계 검사를 재실행한다. 붙어 있는 두 인물은 별도의 분리 경계가 필요하다.

`tests/browser_readability.py`는 54개 포즈, 원래의 중립 그림 범위(설아 234×288, 늑대 201×159, 가시 여왕 224×201), 대상별 상태·보호막·선택 표시, 조작 버튼을 가리지 않는 배치, 아군과 적의 네 타격 인덱스를 검증한다. 몬스터의 투사체는 250–540ms, 타격은 이후 640ms에 네 프레임을 재생한다.
